## Sidebar drawer, responsive breakpoints, tooltips, and 404 page
- **Sidebar (`Sidebar.tsx`):** with the desktop "collapsed" cookie set, several collapsed-state classes lacked an `lg:` prefix and leaked into the mobile/tablet drawer (no brand padding, no icon-label gap, centered profile, clipped logout button, nav not scrollable). Collapsed styles are now `lg:`-only; `railCollapsed` (`isCollapsed && isDesktop !== false`) controls the unlayered `chrome-soft-panel` profile class. Inactive nav items no longer draw a border box.
- **Barang breakpoints:** card list below `xl` (table needs about 1,000px), filter toolbar and 6-column stat grid until `2xl`; the Stok Awal column and its footer filler cell show only at `2xl`; tighter cell padding below `2xl`. Result: no horizontal table scroll at 1280px with the sidebar expanded.
- **Tooltips:** new `src/components/GlobalTooltip.tsx` (mounted once in `src/app/layout.tsx`) renders `data-tooltip` and `title` attributes through a portal with the shared `.app-tooltip` style (dark in light mode, slate in dark mode, arrow, flip/clamp, hover devices only). `title` is moved to `data-tip` on first hover to suppress the OS tooltip, with `aria-label` added when the element has no accessible name. The old pseudo-element `[data-tooltip]` CSS was removed; `<Tooltip>` uses the same style.
- **404 (`src/app/not-found.tsx`):** the hard-coded light background made `text-foreground` invisible in dark mode; the page now uses theme tokens with a gradient 404, back and dashboard actions.
- **Verification:** type-check and ESLint passed. Browser: drawer at 375/768px with the collapsed cookie (padding, gaps, profile panel, logout, scroll), collapsed rail and expanded sidebar at 1024/1280px, Barang at 1024/1280/1440/1920px (no table or page overflow, footer total aligned), eight Gudang pages at 375/768/1024px without horizontal overflow, 404 in light and dark, and tooltip placement/colors via DOM measurement. The sidebar cookie was restored afterwards.

## Selection state and modern checkboxes
- **Checkbox (`globals.css`):** all visible checkboxes (not `sr-only`) use a custom appearance: 16px rounded box, primary fill with a check mark when checked, a dash when indeterminate, focus ring, and a dark-mode unchecked style. Size/shape live in `@layer base` so utilities such as `h-5 w-5` still apply; state colors are unlayered so `border-border` cannot override them.
- **Barang selection (`barang/BarangClient.tsx`):** selected rows use `dark:bg-rose-500/[0.07]` instead of the light rose wash that made dark-mode text unreadable; zero values are dimmed by text color instead of `opacity` on `<td>` (opacity also faded the row background inside that cell and produced visible strips); the delete banner has dark-mode colors; the header checkbox shows the indeterminate state when only part of the page is selected.
- **Verification:** type-check and ESLint passed; browser check at 1440px in dark mode with two rows selected (row background, uniform cell opacity, checked/unchecked checkbox colors, header indeterminate, banner color). Selection was cleared with Batal; nothing was deleted.
