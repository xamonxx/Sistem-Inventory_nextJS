## AUD-003: atomic audit logs and idempotent retries
- **Problem:** money/stock mutations wrote the audit log, cache invalidation, and verification URL after commit inside the same `try`; a helper failure reported a saved sale/payment as failed and invited a duplicate retry.
- **Part A (`2cb5d66`):** `logActivity(input, tx)` commits audit rows with the data; `invalidateAfterCommit`/`afterCommit` (`src/lib/postCommit.ts`) never throw; the outer `try` wraps only the transaction. Applied to checkout, invoice payment, return/exchange, NG invoice, NG payment, stock-in, stock correction, and batch stock-in.
- **Part B:** new table `idempotency_keys` (additive). `src/lib/idempotency.ts` replays a committed result for a repeated key and recovers the winner after a concurrent duplicate; `src/lib/requestKey.ts` (`useRequestKey`) keeps one key per attempt and reuses it only after a network failure. Wired into Kasir, invoice payment, Retur, NG create, and NG payment clients, which now also catch network failures.
- **Verification:** type-check, ESLint, security 68/68, `npm run test:idempotency` 6/6; browser checkout with the first response dropped after commit, then retried: one transaction `PC00104`, one payment, one audit row, one key, receipt replayed. `next build` was not run because another session's dev server held `.next`.
- **Deployment prerequisite:** create the table in production before deploying ([[Idempotency-Schema-Rollout]]).

## Kasir checkout survives network failures
- **Trigger:** "Runtime TypeError: Failed to fetch" overlay on `/kasir` after the preview server was stopped while the page was open.
- **Cause:** `createTransaction` was awaited without `try/catch`; a network failure throws instead of returning `{ error }`, so the page fell into the error screen.
- **Fix:** `src/app/(app)/kasir/KasirClient.tsx` catches the failure and shows "Gagal terhubung ke server…" with advice to check transaction history before retrying (a lost response after a server commit could otherwise lead to a duplicate).
- **Verification:** type-check and ESLint passed. Not exercised in the browser (would require a filled cart and stopping the server mid-checkout).
- **Follow-up:** other clients still await server actions without `try/catch` (Non-Gudang invoice payment/edit, Buat Invoice NG, Edit Invoice, Stock In, Non-Gudang Barang/Konsumen).
